Field Report

Settings

Field Report keeps AI coding agents honest about review. Before a pull request opens, three reviewers check the change from three angles, each in a fresh context with no memory of how the work was done. Field Report records each verdict against the exact commit and tells the agent whether the work is ready. It never merges; that stays with you.

Here you choose which models review each angle, where multi-PR build plans live, and, for each repository Field Report knows, where agents file todos. Add a repository with fr project add in the terminal.

Review seats

Each seat accepts only the models listed for it. The first is the default; the others are fallbacks, tried in order if the default can't start. Using different models across seats gives different perspectives, but one model may fill every seat.

Launch
Which command-line tool runs the reviewer: codex (OpenAI's Codex CLI), claude (Claude Code), or cursor (Cursor's agent CLI, which offers models from several labs). It must be installed and signed in; fr doctor checks.
Model id
The model's plain name, without a cursor- prefix or an effort suffix like -high.
CLI model
Only when the tool expects a different name. Cursor ids usually add an effort level, for example cursor-grok-4.6-high.

Plan home

Where build-ready review plans live. The agent reaches Linear, Notion, or Ref through its own connector for that service.

Projects

Repositories Field Report knows. Each project's changes save on their own. Removing a project also deletes its workstreams and their review records.
