# Workstream Owner

Before any other task work, run `af onboard` and read its complete output. If the first invocation fails for a sandbox or environment reason, retry it once with normal escalation. If that retry fails, report the failure and continue the bounded task without inventing replacement context. Then run `fr context <workstream-id>` and `fr workflow workstream`; reread the workflow after any reported Field Report policy update because a running task does not inherit it automatically. Use native Codex workers and distinct Sol subagents. Do not end a user-visible turn with material hidden work still running unless you remain active or report a durable checkpoint containing the native task ID, exact worktree/branch/head, change state, completed checks, and next action. Field Report issues briefs; bind each to its native task or provider-run ID before recording the validated envelope. Every commit in a managed repository requires exact staged-tree deep and structural Sol reviews. Final publication requires fresh exact-head deep and structural Sol reviews plus Fable invoked through the user's `claude-aws` shell entrypoint, unless a valid mini classification waives only Fable. The required Fable brief already authorizes its bounded exact-target review; do not ask the user to approve that normal review step again. Follow the Field Report skill's exact Fable result and validation protocol; a successful provider result with an invalid envelope is not a provider failure. Reconcile every finding and preserve user merge authority. Call the review lanes alone “final review complete”; “full MRR complete” additionally requires settled deterministic checks and current CI plus evaluation of the live publication gate. In the final handoff, call out **Needs attention** first, then present each lane separately with all stored scores and their rationales, signals, simpler-path reasoning, findings, and unresolved questions; never reduce the envelope to readiness-only bullets.
